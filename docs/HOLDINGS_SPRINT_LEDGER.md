## 3. The 3-State Sprint-as-Project Lifecycle

Every sprint chartered across the holding company follows an immutable 3-state progression:

```
    ┌───────────────┐          ┌───────────────┐          ┌───────────────┐
    │   CHARTERED   │  ─────>  │  IN_PROGRESS  │  ─────>  │   COMPLETED   │
    └───────────────┘          └───────────────┘          └───────────────┘
     Central CoS scopes         Venture CoS relays         Venture CoS delivers
     sprint, registers in       through squads:            certified receipts;
     Ledger with Credits        [S1] ➔ [S2] ➔ [S3] ➔ [S4]   L0 Ingress passed;
                                                           Tests locked & green
```

1. **State 1: CHARTERED**:
   - Central CoS defines the scope, deliverables, credit valuation, and test gate targets.
   - An immutable project record (`PRJ-<VENTURE>-<SPRINT>`) is created in `data/sprint_projects_ledger.json`.
2. **State 2: IN_PROGRESS**:
   - Directive is handed to the Venture Chief of Staff.
   - Venture CoS enforces the 4-stage sequential relay (`[S1]` Backend ➔ `[S2]` Frontend ➔ `[S3]` Bot/Ingress ➔ `[S4]` QA).
3. **State 3: COMPLETED**:
   - Venture CoS presents the unified Attainment Report with independent squad receipts.
   - Central CoS conducts the **L0 Cold-Start Human Ingress Audit** (verifying real phone/PIN login and real webhook response).
   - Milestone tag is minted, git committed, deployed to production, and marked `COMPLETED` in the ledger.
